账号角色与权限设计

分别定义模块可见性、数据范围与操作控制权，作为研发实现及验收依据。

角色规则（2026-09-28 更新）

Admin 可见所有模块、所有数据，拥有全部控制权。DevOps 人员可见除平台治理下管理模块以外的所有目录；组织与成员、客户端管理、模型管理、模型配额、超管后台均不可进入。

业务人员进入独立任务首页，以新建任务替代服务目录，不展示目录菜单；保留创作中心、个人中心和消息中心。登录页提供 Admin、DevOps、业务人员三种演示角色。登录后可通过切换角色按钮切换已授权的工作视图，DevOps 与业务人员按双角色账号演示，非 Admin 登录不提供 Admin 切换入口。

以下“用户账号”的目录权限按 DevOps 人员理解，并以以上最新模块规则为准。IM 渠道与日志的数据权限仍限定本人，其他用户数据不可查看或操作。

当前原型仅演示前端角色切换和路由限制，未接入真实认证、服务端授权或数据隔离，不能作为生产安全机制。

数据范围与控制权

对象Admin 账号用户账号
IM 渠道配置可查看所有用户的渠道配置，拥有新增、修改、删除、启停等全部控制权仅可查看当前用户归属的渠道配置与状态；其他用户的渠道不展示，不可修改、删除、启停或绑定操作

普通用户已明确授权的是本人数据的查看与观测。本人数据的新增、编辑、删除、启停等写操作尚未明确授权，不因菜单可见而自动开放；后续按具体操作单独确认。

实现要求

  • 按已登录账号的角色统一控制服务目录、左侧菜单、搜索结果、快捷入口及页面内的关联入口；用户账号不得通过其他入口进入上述受限功能。
  • 组织与成员及超管后台按整个功能组控制权限，子菜单和直接链接遵循同一规则。
  • 用户直接打开受限地址时展示“无权限访问”，相关接口也应校验权限并拒绝请求。
  • 切换账号或角色后重新计算可见菜单；若当前页面已无权限，则返回服务目录。
  • 隐藏“模型管控”不等于禁止用户使用模型；用户可用的模型范围由 Admin 的配置决定。
  • 数据权限必须由服务端根据已认证的当前用户身份校验，不能信任前端传入的用户 ID、筛选条件或隐藏按钮。Admin 全量访问也必须先通过角色校验。
  • 列表、详情、搜索、统计、导出及写操作统一校验数据归属。普通用户篡改记录 ID 或用户 ID 后，不得读取、更新、删除或触发其他用户资源。
  • IM 渠道与调用日志的用户归属字段及关联判定规则须在接口设计中明确；缺失或无法确认归属的数据不得默认向普通用户开放。
  • 退出或切换账号时清除旧账号的数据缓存、列表与统计，避免跨账号数据泄露。

验收标准

  • Admin 登录后，全部模块、所有用户的数据均可访问，并可执行各模块支持的全部控制操作。
  • 用户登录后，五类受限功能不出现在任何菜单及搜索结果中，直接访问也无法绕过权限。
  • 普通用户仍能看到推理模型、多模态模型等其余菜单。
  • 使用用户 A、用户 B 各自的 IM 渠道与调用日志验证：A 只能查看和观测 A 的数据，B 只能查看和观测 B 的数据；Admin 可查看和管理两者。
  • 普通用户在搜索、详情、统计及导出中均不能获取他人数据；更改请求中的记录 ID 或用户 ID 也不能越权读写。
  • 当前用户无数据时展示空状态，不展示其他用户记录作为补位；切换账号后不保留上一账号的数据。
